# Дизайн: поиск минимальных цен на перекупное оборудование

## Цель

Добавить в веб-интерфейс парсера спецификаций отдельную вкладку для поиска минимальных цен в интернете на оборудование, которое завод ВОК-Регион не производит (отсутствует в 1С).

Результаты поиска сохраняются в SQLite, отображаются в интерфейсе и выгружаются в JSON/Excel. Перекупное оборудование **не добавляется** в итоговый XML — XML остаётся только для производимой номенклатуры.

## Контекст

Сейчас при генерации XML все нераспознанные/непроизводимые позиции попадают в `skipped.json`. Среди них:

- вентиляторы;
- клапаны;
- решётки;
- шумоглушители;
- диффузоры и другое оборудование сторонних производителей.

Менеджер вручную ищет цены на эти позиции. Задача — автоматизировать поиск и дать менеджеру готовую таблицу с минимальными ценами, поставщиками и ссылками.

## Решение: бесплатное комбинированное

### Стратегия поиска

1. **Этап 1 — бесплатные источники (параллельно):**
   - агрегаторы поставщиков: `pulscen.ru`, `tiu.ru`, `blizko.ru`;
   - HVAC-специализированные сайты: `ventportal.ru`, `klimatprof.ru` и др.

2. **Этап 2 — fallback:**
   - если на этапе 1 найдено менее 3 релевантных предложений, запускается fallback через поисковики (`yandex.ru`, `google.com`).

3. **Стоп-условие:**
   - собрано 3+ релевантных предложения;
   - либо все источники исчерпаны.

### Стратегия формирования запроса

Используется убывающая точность:

1. `<наименование> <модель>` — например, `Клапан обратный RVN-560`.
2. `<наименование> <производитель> <модель>` — если в данных есть производитель.
3. Если результатов мало — более общий запрос по наименованию.

### Компоненты

#### `price_search/models.py`

```python
class PriceOffer(BaseModel):
    source: str              # pulscen, tiu, ventportal, yandex, ...
    query: str               # по какому запросу найдено
    title: str               # название предложения
    price: Decimal           # цена в рублях
    currency: str            # RUB (после нормализации)
    supplier: str | None     # поставщик
    url: str                 # ссылка
    scraped_at: datetime

class SearchResult(BaseModel):
    item_name: str
    item_size: str
    queries: list[str]
    offers: list[PriceOffer]
    min_price: Decimal | None
    best_offer: PriceOffer | None
    cached: bool
    created_at: datetime
```

#### `price_search/storage.py`

SQLite-база `price_search.db` в корне проекта.

**Таблица `price_offers`:**

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | |
| `item_name` | TEXT | Наименование позиции |
| `item_size` | TEXT | Модель/размер |
| `query` | TEXT | Поисковый запрос |
| `source` | TEXT | Источник |
| `title` | TEXT | Заголовок предложения |
| `price` | DECIMAL | Цена |
| `currency` | TEXT | Валюта |
| `supplier` | TEXT | Поставщик |
| `url` | TEXT | Ссылка |
| `scraped_at` | DATETIME | Дата поиска |
| `is_fallback` | BOOLEAN | Fallback-источник |

Индексы: `(item_name, item_size, scraped_at)`.

Функции:
- `get_cached_offers(item_name, item_size, max_age_days=7)` — проверка кэша.
- `save_offers(...)` — сохранение результатов.
- `get_history(item_name, item_size)` — история поисков.

#### `price_search/engine.py`

`AsyncPriceEngine`:

- принимает список позиций;
- для каждой позиции проверяет кэш;
- формирует поисковые запросы;
- параллельно запускает источники этапа 1 (`asyncio.gather`);
- при необходимости запускает fallback (этап 2);
- фильтрует нерелевантные результаты;
- сортирует по цене;
- сохраняет топ-3 + минимальную цену;
- возвращает `list[SearchResult]`.

#### `price_search/sources/base.py`

```python
class BasePriceSource(ABC):
    name: str

    @abstractmethod
    async def search(self, query: str) -> list[PriceOffer]:
        ...
```

Каждый источник реализует:
- формирование URL поиска;
- `aiohttp`-запрос;
- парсинг HTML через `BeautifulSoup`;
- извлечение карточек товара (название, цена, поставщик, ссылка).

## UI/UX

### Визуальный стиль (референс beszel.dev)

Вкладка оформляется в тёмной теме на основе дизайн-системы `beszel.dev`:

| Элемент | Значение |
|---|---|
| Фон | `#1B1B1F` |
| Основной текст | `#DFDFD6` |
| Акцент / hover / active | `#3E63DD` |
| Вторичный текст | `#98989F` |
| Границы / разделители | `#202127`, `#2E2E32`, `#3C3F44` |
| Карточка | фон `#161618`, скругление `12px`, padding `24px` |
| Кнопка | фон `#161618`, текст `#98989F`, border `1px solid`, скругление `8px` |
| Скругления | `6px`, `12px`, `20px`, `50px` |
| Тени | `rgba(0, 0, 0, 0.1) 0px 12px 32px 0px` |
| Переходы | `0.25s ease`, `0.5s ease` |

**Типографика:**
- заголовки: `Righteous`, веса 400/600/700;
- текст: `Inter`, веса 400/500/600/700;
- фоллбек: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`;
- размер текста: `14px`, заголовков: `16px+`.

**Ограничение Streamlit:** базовые виджеты (`st.button`, `st.data_editor`, `st.selectbox`) нельзя полностью перекрасить без хаков. Поэтому:
- глобальные цвета фона, текста и акцента задаются через кастомный CSS в `st.markdown(..., unsafe_allow_html=True)`;
- таблицы результатов и карточки позиций рендерятся через HTML/CSS вручную;
- нативные виджеты Streamlit остаются в дефолтной светлой/тёмной теме, но вписываются за счёт общего тёмного фона страницы.

### Новая вкладка Streamlit

**Название:** «Цены на перекупное оборудование».

**Структура экрана:**

1. **Заголовок и описание** — H2 `16px`, цвет `#DFDFD6`.

2. **Карточка «Позиции для поиска»** (фон `#161618`, скругление `12px`):
   - таблица позиций со столбцами:
     - `name` — наименование;
     - `size` — модель/размер;
     - `unit` — ед. изм.;
     - `quantity` — количество;
     - `category` — категория (damper, grille, fan и т.д.);
     - ☑️ `search` — искать цену;
     - ☑️ `include_in_report` — включить в отчёт.
   - фильтры по категориям;
   - кнопки «Выбрать все» / «Снять выделение».

3. **Кнопка действия** — «Найти цены» (акцент `#3E63DD`, скругление `8px`).

4. **Прогресс-бар** — визуальный индикатор обработки.

5. **Карточка «Результаты»** (фон `#161618`, скругление `12px`):
   - таблица с колонками:
     - наименование;
     - минимальная цена (акцентным цветом);
     - поставщик;
     - ссылка (кликабельная, hover — `#3E63DD`);
     - дата поиска;
     - кнопка «Показать топ-3».
   - разворачиваемая строка с топ-3 офферами.

6. **Кнопки скачивания отчёта** — `equipment_prices.json`, `equipment_prices.xlsx`.

### Состояние

Используется `st.session_state` для хранения:
- выбранных позиций;
- результатов поиска;
- статуса прогресса.

## Обработка ошибок

| Сценарий | Действие |
|---|---|
| Источник недоступен | `retry` 3 раза, затем пометка failed, переход к следующему |
| Капча / anti-bot | пометка failed, запись в лог |
| Нет результатов | fallback на поисковики |
| Цена в не-рублях | нормализация или пропуск |
| Нерелевантное предложение | фильтрация по ключевым словам запроса |
| Все источники пусты | позиция помечается «Цена не найдена» |

## Кэширование

- Если для позиции есть записи в SQLite моложе 7 дней — используем кэш.
- Кнопка «Искать заново» позволяет игнорировать кэш.
- Кэш общий для всех сессий.

## Интеграция с XML

**Перекупное оборудование не добавляется в XML.**

XML остаётся только для производимой номенклатуры. Результаты поиска цен — отдельный отчёт для менеджера.

## Тестирование

1. **Модульные тесты:**
   - парсинг HTML для каждого источника на фикстурах;
   - нормализация цен;
   - фильтрация нерелевантных результатов;
   - кэширование в SQLite.

2. **Интеграционные тесты:**
   - end-to-end поиск по тестовой позиции;
   - проверка UI-элементов Streamlit (опционально).

3. **Ручная проверка:**
   - сравнение найденных цен с реальными сайтами;
   - проверка релевантности топ-3.

## Ограничения

- Парсинг сайтов может сломаться при изменении вёрстки.
- Капча и anti-bot могут ограничить доступ; в таком случае fallback на поисковики.
- Цены актуальны на момент поиска; кэш 7 дней может устаревать.

# Дизайн: Пресейл-модуль — экспресс-оценка и расчёт смет (ИИ-агент)

Дата: 2026-11-03 (обновлено по расшифровке созвона с Игорем от 03.11.2026).
Статус: **утверждён заказчиком 03.11.2026**.

## 1. Замысел и зачем

Менеджеры («девочки») и роллер (Игорь) получают входящие сметы заказчиков (PDF, Excel,
Word) и не разбираются в их структуре. Сейчас Игорь вручную скармливает сметы ChatGPT
(промпт «разбей на работы/материалы/оборудование + рыночные цены»), упираясь в дневной
лимит ~3 сметы. Рыночные цены ChatGPT неточны (на металл до 50% расхождения).

Модуль автоматизирует этот цикл: принимает смету или уже готовую таблицу, нормализует
толщины металла по таблице Бориса (округление в большую сторону: 0.65 → 0.7), подтягивает
внутренние цены (прайс Бориса, 1С через MCP, веб-источники) и формирует сравнительную
таблицу: 5 колонок рыночной оценки + 5 колонок нашего расчёта.

Инструмент — рабочее место пресейла: история расчётов, обучение на ручных ценах,
совместная работа нескольких менеджеров. Главные пользователи — менеджеры без
технического бэкграунда: простота таблицы важнее всего.

## 2. Этапы (пересмотрено по созвону)

**Этап 0 — «5 колонок справа» (MVP, без LLM-парсинга смет):**
Вход — готовые Excel-таблицы из ChatGPT (3 листа: работы / материалы / оборудование,
5 колонок: наименование, ед.изм, количество, рыночная цена, сумма). Система дописывает
справа 5 колонок с нашими ценами и отдаёт Excel. Детерминированный Python + прайсы.
Цель — заменить ручную подстановку уже на этой неделе.

**Этап 1 — веб-дашборд с мультиюзером:**
Авторизация, история расчётов, экран результата со сводкой и правками, ручная база
цен, прайс работ, дедлайны, бейдж «похожий расчёт», две выгрузки (внутренняя / КП
заказчику). Расчёт как фоновая задача.

**Этап 2 — парсинг сырых смет (LLM):**
Загрузка самой сметы (PDF/Excel/Word/RTF) → Parser Agent извлекает позиции в тот же
внутренний формат, что и таблицы ChatGPT. Снимает лимит ChatGPT и ручной шаг Игоря.
LLM (Kimi — дешевле) только извлекает сущности; вся математика детерминированна.
⚠️ **Ключевое требование: форматы смет кардинально различаются.** Никакой привязки
к конкретному шаблону, именам столбцов («Кол-во» vs «Количество» vs «Qty») или
порядку колонок: LLM маппит произвольную структуру в канонический внутренний формат,
детерминированный код работает только с каноническим форматом. Нестандартное имя
строки/столбца не должно ломать пайплайн — неизвестное уходит в 🔴, а не в ошибку.
Набор фикстур из ~10 смет Игоря должен покрывать разные форматы, тесты гоняют все.

**Этап 3 — проектная документация:**
Сверка позиций сметы с проектной документацией («найди истину»), подсветка расхождений.

## 3. Реальный формат Игоря (по образцам от 03.11.2026, `tmp/igor_samples/lsr_26_09_07/`)

Получены: исходная смета `ЛСР.RTF` (3.2 МБ, RTF с ГЭСН-обоснованиями — входные сметы
бывают и в RTF!), итоговая книга ChatGPT `ИИ Рыночный_расчёт_ЛСР_26-09-07.xlsx`,
восстановленный код расчёта (`build.mjs`, `rates_config.json`, `verify_calculation.py`).

**Структура итоговой книги ChatGPT (это и есть целевой формат выгрузки):**
6 листов: Итог / Работы / Материалы / Оборудование / Исходная ЛСР / Цены и источники.
- Листы категорий — 12 колонок: ID, Позиция ЛСР, Наименование, Ед., Количество,
  Цена за ед., Сумма, «ЛСР, сопоставимо», ID цены, Основание, Примечание.
  Формулы кросс-листовые, итоги сходятся с исходной сметой.
- «Итог» — сводка по категориям: расчёт без НДС / НДС / с НДС / ЛСР / разница.
  НДС 22%, доставка 3%, резерв 15% (из `rates_config.json`).
- «Цены и источники» — ID цены, ориентир, коэффициент, вид основания, источник с URL
  (ПЕКО ВЕНТ, mosng.ru, celsis.ru, uklimate.ru и др. — ~20 источников).

**Что это меняет в плане:**
- Сравнение «наш расчёт vs смета заказчика (ЛСР)» уже заложено в формат — наша
  сравнительная таблица = этот же каркас + блок колонок с внутренними ценами.
- Источники из `rates_config.json` — готовый список сайтов для новых sources
  в `price_search/` (ПЕКО ВЕНТ и др.).
- Парсер смет (этап 2) должен поддерживать RTF, не только PDF/Excel/Word.
- `verify_calculation.py` (Decimal-проверка сумм) — образец для наших тестов
  детерминизма.
- Таблица Бориса всё ещё не прислана — блокер этапа 0 остаётся.

## 4. Категории и бизнес-правила (из созвона)

- Категории — как у Игоря: **работы / материалы / оборудование** (3 листа).
  «Материалы» включают воздуховоды и фасонину (наш металл) и мелочёвку.
- **Таблица Бориса** — получена 03.11: `reference/boris_prices/Прайс прямоуголка из СофтВент.xlsx`
  и `Прайс кругляк из СофтВент.xlsx` (действует с 09.02.2026). Структура богаче,
  чем «материал+толщина → цена»: цена за м² зависит от **материала × толщины ×
  типа изделия** (прямой участок стандартной длины / укороченный / фасонные /
  нестандартные) и класса длины. Материалы: нерж AISI 430/304, рулон оц. 08ПС,
  штрипс оц.; толщины 0.5–1.0. Округление толщины в большую сторону внутри
  материальной группы. Изделие в смете надо классифицировать ещё и по типу
  (прямой/фасонный/нестандарт) и длине — правила типов согласовать с Борисом.
  ⚠️ В таблицах есть подозрительные значения (нерж AISI 304 0.80 дешевле AISI 430
  0.80: 1151 против 5075 в прямоугольном прайсе; повтор 1151 в оц. 0.55) —
  уточнить у Бориса, не опечатка ли.
  Переиспользуем `process_specification_table.normalize_thickness` / `gost_min_thickness`.
- **Штуки → м²**: по редактируемой таблице коэффициентов по типам изделий
  (пример Игоря: 100 шт × коэффициент = 41 м²). Детерминированно.
- **Работы**: рыночная цена × ~1.5 (наценка монтажников/налоги); прайс work_rates
  семенируется этим правилом, правится в UI.
- **Мелочёвка** (болты, анкеры и т.п.): в 1С не ищем — берём розницу из
  `price_search/` как есть, помечаем источником.
- **Оборудование**: 1С MCP (поиск номенклатуры, цена) → ручная база →
  `price_search` → 🔴.
- **Рыночная колонка**: из `price_search` (реальные источники), не из ChatGPT —
  цены ChatGPT остаются только как «колонка из исходной таблицы», если она есть.

## 4. Цели / Не-цели / Анти-цели

**Цели:**
- ≤ 30 сек на 100–200 позиций (батч-запрос цен к 1С одним вызовом на смету).
- Классификация: работы / материалы / оборудование.
- Нормализация толщин детерминированным кодом; статусы 🟢 точно / 🟡 округление
  толщины / 🔴 нет цены.
- Сводка: итог заказчика, наш итог, дельта, маржа, разбивка по категориям.
- Правки в браузере (цена, толщина, категория) с детерминированным пересчётом и
  построчным логом (автор, было→стало).
- Выгрузки Excel: (а) внутренняя сравнительная таблица для Игоря (5+5 колонок),
  (б) КП заказчику без внутренних цен и маржи.
- Мультиюзер: менеджеры видят, открывают и редактируют расчёты друг друга.
- Ручная база цен: «описание → цена, дата», авто-подстановка в новых расчётах.
- Дедлайн тендера + сортировка/подсветка в истории; бейдж «похожий расчёт».
- Учёт расхода токенов LLM в логах (мотивация этапа 2 — лимиты ChatGPT у Игоря).

**Быстрые итерации после (в архитектуре учесть, не делать):**
- Сравнение версий расчёта после правок; «превратить расчёт в заказ 1С»
  (`generate_order_xml`); статистика конверсии по менеджерам.

**Не-цели:**
- Приём смет письмом/выделенным ящиком — смета приходит файлом, загрузка руками.
- Полноценный ACL/роли — все менеджеры равноправны.
- PostgreSQL — SQLite (WAL) достаточно для 5–10 одновременных пользователей.

**Анти-цели:**
- LLM считает геометрию/цены «в уме» — вся математика только Python.
  Риск из созвона: LLM путает длину с шириной → валидация после извлечения
  (несостыковка суммы строк с итогом сметы → подсветка).
- 🔴 в каждой смете по работам → недоверие к статусам.
- Утечка внутренних цен/маржи в файл для заказчика (тест).

## 5. Ограничения и переиспользование

- Репозиторий общий с существующим кодом; весь накопленный пайплайн используется
  как библиотеки: парсеры (`pdf_spec_extractor`, `project_spec_xlsx`, `zayavka_xlsx`),
  LLM-слой (`llm_client`, `llm_row_fallback`, `llm_document_fallback`), нормализация
  толщин (`process_specification_table`), MCP-доступ к 1С (`execute_code`,
  `docs/ЛОГИКА_РАСЧЕТА_ЦЕН_1С.md`), `price_search/` (AsyncPriceEngine +
  tiu/pulscen/blizko + кэш), `report_xlsx`.
- ⚠️ Факт: существующий `web_app.py` — Streamlit-приложение (без сессий, фоновых
  задач, совместного редактирования). **Открытый вопрос №1** (см. §8): пресейл —
  новое FastAPI-приложение в этом же репозитории vs допиливание Streamlit.
  FastAPI в репо уже есть как образец — `bitrix_bot/server.py`.
- Батч-доступ к ценам 1С: один вызов `execute_code` на смету с массивом позиций
  вместо сотен отдельных запросов (иначе 30 сек недостижимы).
- Новые библиотеки: instructor или pydantic-ai (structured output), rapidfuzz
  (похожие позиции/ручная база), Docling — только если текущие парсеры не тянут
  форматы смет. FastMCP — опционально позже (учесть GHSA-gpgx-58w2-xwwf).

## 6. Как устроено (решённые части)

### Путь менеджера
1. Вход (логин/пароль, сессия) → общая история расчётов, сортировка по дедлайну,
   подсветка просроченных.
2. Загрузка файла, опционально заказчик/тендер/дедлайн → бейдж «похожий расчёт».
3. Прогресс по этапам; расчёт — фоновая задача (образец `bitrix_bot/queue.py`),
   общий кэш цен между пользователями. При сбое LLM расчёт не прерывается —
   строки уходят в 🔴.
4. Экран результата: сводка (итоги, дельта, маржа, разбивка работы/материалы/
   оборудование) + таблица со статусами 🟢🟡🔴, фильтр по 🔴, правки с пересчётом.
5. Выгрузки: «Excel для Игоря» (5+5 колонок) и «КП заказчику» (без внутренних).
6. История: расчёт открывается в последнем состоянии; построчный лог правок.

### Мультиюзер
- Пользователи из конфига (логин/хэш пароля), сессии-cookie.
- SQLite (WAL): users, estimates, estimate_items, item_edits, manual_prices,
  work_rates, unit_conversion (шт→м² коэффициенты).
- Общий доступ без блокировок; конфликты решаются логом правок. Кэш цен общий.

### Пайплайн (детерминизм)
- Этап 0/1: вход — таблица ChatGPT; классификация уже есть (3 листа).
- Этап 2: Parser Agent (LLM, structured output) извлекает позиции из сырой сметы;
  Python: толщины, шт→м², цены, суммы, маржа, валидация итогов.
- Цены по категориям: материалы — таблица Бориса / 1С; оборудование — 1С MCP →
  ручная база → price_search; мелочёвка — price_search; работы — work_rates.

## 9. Критерии приёмки

- Ноль LLM-математики: тесты на геометрию, округление толщин, шт→м², суммы.
- Этап 0: на 3 реальных таблицах ChatGPT из образцов — 5 колонок с нашими ценами
  без ручных правок кода, расхождение с ожиданиями Игоря только в 🔴-строках.
- ≥2 типа MCP-вызовов к 1С работают (цена материала, поиск номенклатуры).
- 100–200 позиций ≤ 30 сек.
- Два менеджера одновременно правят общий расчёт — правки не теряются, видны в логе.
- КП-выгрузка не содержит внутренних цен/маржи (тест).
- Ручная цена, введённая один раз, подставляется в новом расчёте автоматически.

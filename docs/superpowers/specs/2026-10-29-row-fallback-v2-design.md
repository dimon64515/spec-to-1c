# Дополнение к дизайну: row-нормализация без белого списка + починка количества

Дата: 2026-10-29
Статус: утверждено пользователем (скоуп «всё, кроме м² и 20-x»)
База: docs/superpowers/specs/2026-10-28-llm-row-normalizer-design.md

## Повод (боевые данные, воспроизведение job 168, 29.10)

- 47 skipped = 35× «Не удалось распознать количество (0)» (qty=0, unit='' —
  сломанный детерминированный разбор заявки) + 7× покупное + 4× «размер / тип»
  + 1× «Отсутствует размер».
- Двойники: у 27 из этих строк LLM-версии УЖЕ в заказе (doc-fallback
  recovered=27), но сломанные оригиналы остались в skipped — отчёт показывает
  одну позицию и в «Загружено», и в «Пропущено».
- Баг row-нормализатора: протокол брал qty/unit из исходной строки → при
  qty=0/unit='' нормализация 5/5 давала 0 восстановлений (лог 29.10 08:57
  «normalized: 5/5», meta row_fallback_recovered=0).

## Изменения

1. **Blacklist вместо whitelist**: нормализуются ВСЕ skipped, кроме
   м²-агрегатов (reason начинается с «Единица м²» или unit ∈ {м2, м²}).
   Blocked 20-1/20-2/20-9 в skipped на этом этапе отсутствуют (фильтр
   `_filter_blocked_articles` стоит после row-fallback) — отдельное
   исключение не требуется.
2. **Протокол: LLM возвращает {name, size, unit, quantity}**. Валидация:
   - name — якорь как раньше (общий токен ≥3 с исходником);
   - quantity — целое > 0, обязано встречаться среди цифровых токенов в
     окне до 30 символов после ВХОЖДЕНИЯ name в тексте документа
     (re-use логики doc-fallback: `_name_positions`/`_quantity_matches`;
     текст документа получать через extract_document_text по pdf_path);
   - unit ∈ whitelist {шт, м, м2, м²};
   - size — подстрока исходника как раньше.
3. **Чистка двойников**: после успешного мерджа удалять из skipped строки,
   чья нормализованная lower-name совпадает с lower-name восстановленной
   LLM-строки И чья причина — «Не удалось распознать количество» (детерминированный
   сломанный близнец). Остальные skipped не трогаем.
4. **Сигнатуры**: `normalize_rows(rows, cfg=None, runner=None, deadline=None,
   text=None)`; `run_row_fallback(success, skipped, cfg=None, pdf_path=None)` —
   текст извлекается внутри (лениво, только если есть квалифицируемые строки).
   `process_pdf_to_positions` передаёт pdf_path; web_app — свой temp-путь.
5. Покупные позиции нормализуются наравне с прочими (решение пользователя):
   скорее всего снова отклонятся `process_rows` по «нет артикула» — остаются
   в skipped честно.

## Ожидаемый эффект (job 168)

«Загружено» ~55–58 из 74; «Пропущено» — только реальные отказы
(~7 покупных + мусорные строки типа шапки «№ Наименование В1 Кол-во»).

## Тесты

- quantity/unit от LLM принимаются при подтверждении текстом; отклоняются
  при несовпадении с текстом.
- м²-строки не нормализуются (blacklist).
- двойник с «количество (0)» исчезает из skipped при восстановлении.
- blocked-строки (20-x) — регрессионный пин: не появляются в success
  (фильтр после, как раньше).

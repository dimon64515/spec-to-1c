# Дизайн: Excel-отчёт после обработки файла + round-trip правки через Excel

Дата: 2026-09-07 (обновлено: добавлена фича 2 round-trip)
Статус: утверждён пользователем, ожидает ревью спеки

## Цель

После обработки PDF-спецификации формировать Excel-отчёт с результатами загрузки в 1С:
какие позиции загружены, какие пропущены (с причинами), какие ошибки вернула 1С,
и отдельно — «перекупное» (покупное) оборудование, не вошедшее в заказ, с размерами
и материалами в соседних столбцах. Отчёт должен:
1. прикрепляться к сообщению в чат Битрикс (вместо текущей нарезки текстовых сообщений);
2. скачиваться в Streamlit-интерфейсе рядом с кнопкой скачивания XML.

## Контекст кода

- Пайплайн: `bitrix_bot/pipeline.py` — `run_pipeline()` возвращает датакласс
  `PipelineResult` (bitrix_bot/pipeline.py:12-22): `file_name`, `order_number`,
  `loaded: List[dict]`, `skipped: List[dict]`, `errors_1c`, `warnings_1c`, `raw_text`.
  Это единственный источник данных для отчёта.
- Загруженная позиция: `article, params {A0,B0|D0}, quantity, material_code, thickness,
  connection_0..3, system, comment` (`process_specification_table.py`, `_finalize_row`).
- Пропущенная позиция: `{name, size, unit, quantity, reason, ocr_warning?}`.
  **Пробел:** `material` и `thickness` вычисляются в `parse_row` до возврата скипа
  (~process_specification_table.py:1061-1081), но в skip-dict не кладутся.
- Признаки перекупного в `reason`:
  - «Покупная позиция (гибкий воздуховод/трубопровод/изоляция)» (~:1091-1100);
  - «Покупная арматура (брендовый клапан/шумоглушитель)» (~:1105-1112).
- Второй источник пропущенного: автомаппинг оборудования (`map_customer_equipment.py:145-165`),
  ключи `raw_name/model/manufacturer/unit/quantity` — это покупное оборудование,
  попадает в лист «Перекупное».
- Категории перекупного уже определены: `EQUIPMENT_PTYPES` + `detect_product_type` +
  `_normalize_skipped_for_prices` (web_app.py:46-120).
- Текущий текстовый отчёт: `bitrix_bot/report.py` (`build_report`, нарезка по 3500 символов),
  отправка через `BitrixClient.send_message` → `im.message.add` (bitrix_client.py:32-33).
  Отправки файлов нет. Права вебхука включают `disk` (bitrix_bot/README.md:42).
  Follow-up в BACKLOG.md:297(а) предлагает именно файл-отчёт вместо нарезки.
- Веб-интерфейс: Streamlit `web_app.py`; скачивание XML — `st.download_button`
  (web_app.py:366-371), skipped.json — :373-379. Результат хранится в `st.session_state`.
- openpyxl и pandas уже в requirements; образец Excel-выгрузки: price_search/ui.py:165-193.
- Тесты: pytest-функции без классов, локальные stub-моки (`tests/test_bitrix_*.py`),
  чтение xlsx через openpyxl из BytesIO (tests/test_api.py:36).

## Архитектура

Общий модуль генерации + две точки интеграции (битрикс-бот и Streamlit).
Один источник истины для формата отчёта — изменения колонок правятся в одном месте.

### 1. `report_xlsx.py` (корень репозитория)

Виден и `bitrix_bot` (пакет уже импортирует модули из корня), и `web_app.py`.

API:
```python
def build_excel_report(res: "PipelineResult") -> bytes  # xlsx-контент
```
(импорт `PipelineResult` — под тип-checking/typing, чтобы избежать циклического импорта:
`bitrix_bot/pipeline.py` будет импортировать `report_xlsx`.)

Реализация: openpyxl Workbook в BytesIO, по образцу price_search/ui.py:184-193.

**Листы и колонки:**

- **«Загружено»**: Артикул, Размер A, Размер B (или D), Кол-во, Материал, Толщина, Система, Комментарий.
  Размеры из `params` (A0/B0 для прямоугольных, D0 для круглых; пустой столбец для нерелевантного).
- **«Пропущено»**: Наименование, Размер, Кол-во, Ед., Причина. Только НЕ-перекупные скипы
  (не распозналось / не сматчилось).
- **«Перекупное»**: Наименование, Категория (классификация по `detect_product_type`/`EQUIPMENT_PTYPES`),
  Размер, Материал, Толщина, Кол-во, Ед., Производитель, Модель.
  Попадают: скипы с причинами «покупная позиция» / «покупная арматура» + скипы автомаппинга
  оборудования (`raw_name/model/manufacturer`). Материал/толщина — после доработки парсера
  (см. п.2); не распознан → пустая ячейка.
- **«Ошибки 1С»**: сводка сверху (Заказ №, строк загружено, ошибок, предупреждений),
  затем таблица: Тип (ошибка/предупреждение), Текст. Пусто → лист только со сводкой.

Разделение «пропущено vs перекупное» — детерминированная функция по `reason`
(без LLM, без новых зависимостей), тестируется.

Оформление: жирная шапка, автоширина колонок, закрепление первой строки.

### 2. Доработка парсера (`process_specification_table.py`)

В точках формирования skip-dict (~:1096-1121) добавить уже вычисленные `material`
и `thickness`. Существующее поведение (ключи, причины) не меняется — только новые поля.

### 3. Отправка в Битрикс

- `bitrix_bot/bitrix_client.py`: новый метод `send_file(chat_id, filename, content: bytes, caption: str)`.
  Загрузка файла через REST `disk.folder.uploadfile` (права `disk` есть), затем
  `im.message.add` с прикреплением файла. Точный формат вложения (параметр `ATTACH`)
  уточняется на реализации; фолбэк — сообщение со ссылкой на файл диска.
- `bitrix_bot/server.py` (`make_handler`, :24-39): после успешного пайплайна отправлять
  файл + краткое резюме (заказ №, загружено X, пропущено Y, перекупное Z, ошибок N).
  Текущая нарезка `build_report` убирается из этого пути.
- Сбой отправки файла **не ломает заказ**: при ошибке — фолбэк на текущий текстовый
  `build_report` (как сейчас), ошибка логируется.
- Имя файла: `report_order_<N>.xlsx` (ASCII — безопасно для disk upload).

## Фича 2: правка отчёта в Excel и пересоздание заказа (round-trip)

Расширение фичи 1: скачанный отчёт можно отредактировать в Excel и загрузить обратно
(веб-интерфейс или чат Битрикс) — создаётся **новый** заказ в 1С с правками,
старый заказ удаляется менеджером вручную (авто-пометка на удаление сознательно
не делается — она требует доработки BSL на стороне 1С).

### Изменения формата отчёта (обратная совместимость чтения)

- Лист **«Загружено»**: добавляются колонки «Соединение 0..3» (из `connection_0..3`)
  — они нужны, чтобы восстановить позицию для повторной загрузки.
  Удаление строки с листа = позиция исключается из нового заказа.
- Листы **«Пропущено»** и **«Перекупное»**: добавляется колонка **«Включить в заказ»**
  (значение «да» / пусто). «да» → позиция возвращается в заказ через повторный
  подбор аналога (`match_description_to_product`). Аналог не найден → позиция
  остаётся пропущенной с причиной «Аналог не найден при повторном включении».
- Лист **«Ошибки 1С»**: сводка дополняется ячейкой **«Номер заказа»** = `order_number`.
  Это ссылка на заменяемый заказ; читается при обратной загрузке.

### Парсер обратно: `parse_edited_report(content: bytes) -> EditedReport`

В том же модуле `report_xlsx.py`:
```python
@dataclass
class EditedReport:
    positions: list[dict]        # формат load_order_to_1c (article, params, quantity, material_code, thickness, connection_0..3, system, comment)
    include_skipped: list[dict]  # позиции с «Включить в заказ» = да
    replaced_order: str | None   # из сводки листа «Ошибки 1С»
```
Валидация с понятными ошибками пользователю: неизвестные листы/заголовки, битые
числа в количестве/размерах, пустой лист «Загружено». При ошибке валидации
ничего в 1С не создаётся.

### Поток пересоздания (общий для веб и бота)

1. `parse_edited_report` → валидация.
2. Для `include_skipped` — повторный матчинг аналогов; успешные добавляются в positions.
3. `load_order_to_1c(positions, ..., order_comment="... | Заменяет заказ №N (исправлено из отчёта)")`.
4. Результат оборачивается в новый `PipelineResult` (загруженные = positions,
   пропущенные = include_skipped без аналога) → генерируется новый Excel-отчёт
   → отправляется в тот же канал (чат/веб).

### Интеграция

- **Веб (`web_app.py`)**: блок «Пересоздать заказ из отчёта»: `st.file_uploader`
  (.xlsx) → diff-сводка перед подтверждением (сколько позиций в новом заказе,
  что исключено, что включено обратно, какой заказ заменяется) → кнопка
  «Создать новый заказ» → новый номер + новый Excel на скачивание.
- **Битрикс (`bitrix_bot/`)**: входящее сообщение с вложением `.xlsx` → скачивание
  вложения через REST → тот же поток → новый отчёт в чат. Метод скачивания
  вложений уточняется на реализации (im/disk REST, права `disk`/`im` есть).

### Обработка ошибок (round-trip)

| Сценарий | Поведение |
|---|---|
| Нет «Номера заказа» в сводке | Создаём новый заказ, комментарий без «Заменяет №N» |
| Включённая позиция без аналога | Новый заказ создаётся без неё; в итоговом отчёте — в «Пропущено» с причиной |
| Битый / чужой xlsx | Понятное сообщение об ошибке, в 1С ничего не создаётся |
| Пустой лист «Загружено» + нет включённых | Отказ: нечего грузить |

### Тесты (round-trip)

- `parse_edited_report`: чтение всех листов, номера заказа, включённые позиции;
  ошибки валидации.
- Сквозной тест потока: отредактированный xlsx (смена толщины + исключение строки
  + включение перекупной) → mock `load_order_to_1c` → ассерты на positions и
  комментарий «Заменяет №N».
- Тест: include_skipped без аналога остаётся пропущенной.

## Обработка ошибок

| Сценарий | Поведение |
|---|---|
| Сбой disk-upload / attach в Битрикс | Фолбэк на текстовый отчёт, лог ошибки, заказ не трогаем |
| Нет пропущенных / перекупного / ошибок 1С | Лист присутствует, только шапка (единый формат файла) |
| Материал не распознан у перекупного | Пустая ячейка, не «—» |
| Веб: xlsx уже сгенерирован | Переиспользуем из session state, не генерируем дважды |

## Что сознательно НЕ делаем (YAGNI)

- Отдельная настройка состава колонок / включаемости листов.
- Excel-отчёт для ценового поиска (вкладка цен — отдельная фича, уже есть выгрузка).
- Удаление модуля `bitrix_bot/report.py` — он остаётся как фолбэк.

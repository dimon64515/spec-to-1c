# Анализ HTTP-сервиса «ПолучениеЗаказов» (NewZakazPost)

Дата: 19.09.2026
База: `KA_vok-region_test` (WIN-DM2PLAHAIIL), MCP 6005 (execute_code).
Источник: модуль HTTP-сервиса `Общие → HTTP-сервисы → ПолучениеЗаказов` (newzakaz.txt).

## Контракт (как реализовано)

- `POST https://www.1c-woc.ru/KA_vok-region_test/hs/Zakaz/zakaznew`
  (корневой URL сервиса `Zakaz`, шаблон `NewZakaz`; проверено в метаданных базы).
- Заголовок `key: <секрет>` — без него 500 «Нет установленного ключа обработки».
  Секрет хранить только в локальном конфиге (не коммитить). В исходнике модуля
  был зашит литерал `FPPA` — уточнить у разработчика, что сейчас в коде.
- Тело: JSON `{"positions": [...]}` или голый массив.
- Позиция: `article`, `comment`, `qty`, `material`, `conn0`, `conn1`, `shina`,
  `thickness`, `params` (A0, B0, A1, B1, L0, D0, L1, D1, R, u, L2, p, A2, B2, D2,
  a1, b1, l1, d1).
- Ответ 200: `{"Документ": "асСпецификацияЗаказа ... от ...", "МассивПроблем": [...]}`
  (МассивПроблем = отчёт о неизвестных ключах позиции/params; на заполнение не
  влияют — `ЗаполнитьЗначенияСвойств` их игнорирует, проверено).
- Коды ошибок: 500 — нет ключа; 501 — битый JSON; 502 — неизвестная структура
  JSON; 503 — не удалось записать документ.

## Живой тест публикации (19.09.2026)

- Публикация существует: `https://www.1c-woc.ru/KA_vok-region_test/...`
  обрабатывается «1C Web-service Extension» (IIS 10, обработчик ISAPI дошёл
  до 1С). Ранее с сервера 1С порт 80/localhost не отвечал — сайт привязан к
  443/другому узлу IIS.
- **Рабочий URL:** `POST https://www.1c-woc.ru/KA_vok-region_test/hs/Zakaz/NewZakaz`
  (в метаданных: сервис `ПолучениеЗаказов`, корневой URL `Zakaz`, шаблон
  `/NewZakaz`, обработчик `NewZakazPost`). URL `/hs/Zakaz/zakaznew` из
  переписки — 404: такого шаблона нет.
- **Аутентификация:** публикация требует Basic Auth пользователя ИБ 1С.
  Подходит сервисный пользователь `HTTP_Service1` с ПУСТЫМ паролем
  (пароль в ИБ не установлен). Пара `1cwww-xh1e64-t673cd / jC0dn-...` —
  НЕ учётка 1С, такого пользователя в базе нет (вероятно, доступ к сайту
  1c-woc.ru).
- **HTTP 403 «Недостаточно прав для использования ресурса с данным HTTP
  методом»**: у `HTTP_Service1` не было ролей. Роль `АСУ_HTTPСервисы`
  выдана через MCP 6005 (второй вызов прошёл; первый завис по таймауту —
  ПИБ.Записать() из HTTP-контекста работает медленно/нестабильно).
- После выдачи роли: `/hs/dt` (ПередачаДанных) отвечает уже НЕ 403, а 400
  «Не указан заголовок управления сеансами» — модуль отработал, роль рабочая.
  А `/hs/Zakaz/NewZakaz` — ВСЁ ЕЩЁ 403. **Вывод: в роль `АСУ_HTTPСервисы`
  не добавлено право «Использование» на новый HTTP-сервис
  `ПолучениеЗаказов`** (сервис добавили в конфигурацию, роль не обновили).
- **Задача 1С-разработчику:** добавить в роль `АСУ_HTTPСервисы` право
  «Использование» на HTTP-сервис `ПолучениеЗаказов` (или создать отдельную
  роль под загрузку заказов с минимальным набором прав по ТЗ п. 7).
- После выдачи права повторить: неверный/пустой `key` → 500 «Нет
  установленного ключа обработки»; валидный `{"positions":[]}` → 200 с
  `Документ`; 1 позиция → сверка заполнения и пометка на удаление.

## Переработка модуля под ТЗ (19.09.2026)

Новая версия модуля: `tools/as_order_loader/http_service_newzakaz.bsl`
(дубликат с именем `newzakaz.txt` в корне репозитория — чтобы просто
заменить код модуля в конфигураторе). Загружается вместо текущего модуля
сервиса «ПолучениеЗаказов». Полный порт логики `as_order_loader.bsl` + создание
Характеристики из `build_execute_payload.py` + контракт ТЗ:

- URL прежний: `POST /hs/Zakaz/NewZakaz` (шаблон `/NewZakaz`).
- Заголовок `X-API-Key` (совместимость: `key`), секрет — в одной функции
  `ОжидаемыйКлючAPI()` (проверить/сменить значение перед внедрением).
- Тело: `order_comment`, `request_id`, `positions` (ТЗ п. 3); принимается и
  голый массив позиций.
- Ответ: `{Успех, НомерЗаказа, Ошибки, Предупреждения}`, UTF-8, Content-Type
  application/json. Бизнес-ошибки (не найден продукт/материал/шина,
  неизвестный код соединения) → документ создаётся, Успех=false, HTTP 200.
  Исключение → HTTP 500, Успех=false. Нет ключа → 403. Битый JSON → 500.
  Пустые positions → 400.
- Идемпотентность: маркер `[req:<request_id>]` в конце комментария документа
  (тот же формат, что в `extension/ДополнениеHTTP.bsl`); повторный вызов с тем
  же request_id вернёт номер ранее созданного документа.
- Расчёт цен/площадей — через `асВводНовогоЗаказа.РедактироватьВсеНаКлиенте_
  ДляИзмененныхВМодуле` (паритет с кнопкой «Расчёт»), производные размеры из
  `асНастройкиПродукции`, шины, соединения, t/t2/np, Продукт и т.д.

Осталось для внедрения:
1. 1С-разработчику: выдать роли `АСУ_HTTPСервисы` право «Использование» на
   HTTP-сервис `ПолучениеЗаказов` (сейчас 403 до модуля) + права на объекты
   по шапке модуля.
2. Внедрить модуль, прогнать приёмку: smoke (2–3 позиции, сверка S/цен с
   интерактивным расчётом) → идемпотентность (тот же request_id → тот же
   номер) → полная фикстура `tests/fixtures/order_positions_full.json`.
3. Python-сторона готова: `order_client.HttpServiceTransport`
   (`order_service_url` + `order_service_key` в `bitrix.local.yaml`).

## Критические расхождения с ТЗ (`docs/ТЗ_HTTP_СЕРВИС_ЗАГРУЗКА_ЗАКАЗА_1С.md`)

1. **Нет расчёта цен.** Не вызывается
   `асВводНовогоЗаказа.РедактироватьВсеНаКлиенте_ДляИзмененныхВМодуле`,
   производные размеры из `асНастройкиПродукции` не считаются. Эмуляция:
   `ЦенаЕд`, `S`, `np`, `t`, `t2`, `Материал2` — пустые. Главное требование ТЗ
   («со штатным расчётом цен») не выполнено.
2. **Не заполняются ключевые реквизиты:** `thickness` → `t`/`t2` и `shina` →
   `МатериалНаСоединение0/1` (ключи объявлены «известными», но в коде не
   используются); не ищется `асПродукция` (`Продукт`, `АртикулПродукции`,
   `АртикулГруппы`, `ГруппаПродукцииСтр`, `СечениеСтр` — пустые);
   **не создаётся `Характеристика`** — без неё «Оформить заказ» падает
   «Рабочее наименование не уникально» (см. `docs/BACKLOG.md`).
3. **`comment` пишется в `КомментарийКПродукции`**, проверенный путь
   (`tools/as_order_loader/as_order_loader.bsl`) — в
   `КомментарийКПродукцииИзOnLine`. Комментарий вероятно потеряется.
4. **Нет `order_comment`, `request_id`/идемпотентности.** Бизнес-ошибки
   (не найден артикул/материал) — только `СообщитьПользователю`: документ
   записывается с пустой номенклатурой, ответ 200 ОК.
5. **Несовместим с `order_client.py:HttpServiceTransport`.** Транспорт шлёт
   `X-API-Key`, 1С читает `key` → 500, а транспорт любой 5xx без поля «Успех»
   трактует как ретрай-эбл сбой (`raise_for_status`). Ответ `{Документ,
   МассивПроблем}` без `Успех`/`НомерЗаказа`/`Ошибки` транспорт не распарсит.
6. Коды 500/501/502/503 под бизнес-ошибки/битый JSON конфликтуют с ретрай-логикой
   Python (дубли заказов при ретрае).

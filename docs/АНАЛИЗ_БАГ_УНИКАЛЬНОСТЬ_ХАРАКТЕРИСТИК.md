# Баг «Оформить заказ»: «Значение поля Рабочее наименование не уникально» — корневая причина

Дата: 20.09.2026. Статус: **корневая причина найдена и подтверждена end-to-end на тестовой базе**;
код-фикс формы — за 1С-разработчиком, обход в загрузчике (execute_code-фолбэк) — внедрён.

## Симптом

«Оформить заказ» в обработке `асВводНовогоЗаказа` падает, вся транзакция оформления откатывается.
Стек (журнал регистрации, 05.09.2026 23:20–23:21, сессия 27847):

```
{Обработка.асВводНовогоЗаказа.Форма.Форма.Форма(2672)}: Спр.Записать();
{Обработка.асВводНовогоЗаказа.Форма.Форма.Форма(22200)}: СсылкаНаДокумент = ОформитьЗаказНаСервере_УТ();
по причине: Значение поля "Рабочее наименование" не уникально
```

## Корневая причина (три звена, каждое доказано прогонами через MCP)

### 1. Имена характеристик с пробелами по краям — легальны и уже есть в базе

Обработка генерирует имя как `""+Стр.Обозначение + "  " + СОКРЛП(материал.НаименованиеДляПечати)`
(модуль формы, `ОформитьЗаказНаСервере_УТ`, ~стр. 2649 дампа `docs/модуль загрузки с сайта.txt`).
При **пустом обозначении** имя начинается с двух пробелов: `"  Рулон оц.(08ПС)0.55"`.
Такие элементы существуют (созданы этим же кодом ранее), пример у владельца
«Дроссель-клапан круглого сечения»: `"  Рулон оц.(08ПС)0.55"` (21 символ, не помечен на удаление).
По базе: 61 имя с хвостовыми пробелами, 15+ имён с ведущими пробелами.

### 2. Поиск в форме асимметричен — мина не находится

`НайденаяХарактеристикаУТ` (дамп, стр. 5144–5206) сравнивает:

```bsl
Если ""+Строка(Обозначение)+ "  "+ СОКРЛП(Строка(Материал.НаименованиеДляПечати))
      = СОКРЛП(Строка(ВыборкаДетальныеЗаписи.Наименование)) Тогда
```

Левая (сгенерированная) часть **не** нормализуется, правая (хранимое имя) — обёрнута в `СОКРЛП`.
Для пустого обозначения: сгенерированное `"  Рулон оц.(08ПС)0.55"` ≠ `СОКРЛП("  Рулон оц.(08ПС)0.55")`
= `"Рулон оц.(08ПС)0.55"` → **промах**, хотя элемент в базе есть.
Подтверждено прогоном: «поиск как в форме: найдено=Нет; симметричный поиск: найдено=Да».

### 3. БСП-контроль уникальности не совпадает с поиском формы

Контроль в `ПередЗаписью` справочника `ХарактеристикиНоменклатуры` (модуль объекта, стр. 100,
константа `КонтролироватьУникальностьРабочегоНаименованияНоменклатурыИХарактеристик`)
сравнивает имена по **СокрП** (хвостовые пробелы не значимы), **в пределах владельца**
(проверено: запись имени, существующего у другого владельца, — успешна).
Промах поиска → форма идёт в ветку создания → БСП видит дубликат
(для пустого обозначения строки буквально равны; для хвостовых пробелов — равны по СокрП) →
`"не уникально"` → откат транзакции оформления целиком.
Подтверждено прогоном в откатываемой транзакции: создание `"  Рулон оц.(08ПС)0.55"`
у дросселя → точно та же ошибка.

Дискриминационные тесты контроля БСП (каждый в своей откатываемой транзакции):

| Вариант имени | Исход |
|---|---|
| существующее имя + хвостовой пробел | ОШИБКА «не уникально» |
| то же с одинарным внутренним пробелом вместо двойного | ЗАПИСАЛОСЬ |
| то же с ведущим пробелом | ЗАПИСАЛОСЬ |
| имя, существующее только у другого владельца | ЗАПИСАЛОСЬ |
| уникальное имя | ЗАПИСАЛОСЬ |

## Хронология инцидента 860

1. 23:16:23 — загрузчик создал заказ №000000860 (прямой путь), характеристики созданы/подобраны,
   в т.ч. `"  Рулон оц.(08ПС)0.55"` у дросселя (следов в форме до этого не было).
2. 23:20–23:21 — пользователь вручную нажал «Оформить заказ» в обработке с той же номенклатурой;
   строка с пустым обозначением и материалом «Рулон оц.(08ПС)0.55» → поиск промахнулся →
   создание отклонено БСП → падение. Повторная попытка через минуту — то же.

## Фикс

### Внедрён (Python-сторона, execute_code-фолбэк) — РЕШЕНО НА НАШЕЙ СТОРОНЕ 20.09.2026

`tools/as_order_loader/build_execute_payload.py`:
1. Создание характеристики с чистым именем — `СпрХ.Наименование = СокрЛП(Канд[0])`
   (раньше при пустом материале создавалось имя с хвостовыми пробелами).
2. Фолбэк-поиск `СокрЛП(Наименование) = СокрЛП(кандидат)` в пределах владельца
   после точного `НайтиПоНаименованию`. Свойство: СокрЛП-совпадение ⇒ СокрП-совпадение
   ⇒ БСП дала бы отказ, поэтому создание выполняется только при гарантированном
   отсутствии дубликата. Проверено на живой базе против реальной мины;
   юнит-тесты зелёные (28 passed).

Плюс разовая чистка существующих мин (см. ниже). HTTP-путь
(`асЗагрузкаЗаказаИзJSON` / `ВОКЗагрузкаЗаказаHTTP`) характеристик не создаёт —
мин из него не возникает. Ручной ввод без пустого обозначения мин не создаёт
(подтверждено наблюдением: вручную баг не воспроизводился). С учётом этого
баг закрыт на нашей стороне полностью; фикс формы 1С ниже — желателен
(гигиена + страховка на случай пустого обозначения вручную), но не блокирует.

### За 1С-разработчиком (модуль формы обработки `асВводНовогоЗаказа`)

Дамп формы: `docs/модуль загрузки с сайта.txt` (это модуль формы; строка 22200 совпадает
со стеком журнала регистрации).

1. **Минимальный фикс — симметричный поиск.** В функциях `НайденаяХарактеристикаУТ` (стр. 5144–5206),
   `НайденаяХарактеристикаБП` (5251–5280), `НайденаяХарактеристикаУНФ` (5321+)
   обернуть сгенерированную (левую) часть сравнений в `СОКРЛП(...)`:
   `Если СОКРЛП(""+Строка(Обозначение)+ "  "+ СОКРЛП(...)) = СОКРЛП(Строка(Выборка.Наименование)) Тогда`
   Тогда существующая мина находится и **переиспользуется**, создание не выполняется,
   БСП не вызывается. Инвариант: СокрЛП-дубль ⇒ СокрП-дубль ⇒ БСП отказала бы,
   значит создание при отсутствии СокрЛП-дубля всегда успешно.
2. **Согласованность формата (опционально, рекомендуется).** При пустом `Стр.Обозначение`
   не допускать ведущие пробелы в имени: `НаименованиеХарактеристики = СОКРЛП(Стр.Обозначение + "  "
   + СОКРЛП(Стр.Материал.НаименованиеДляПечати))` (и аналогично в ветках Материал2/без материала,
   стр. 2636–2667). Старые «мины» после фикса (1) находятся поиском по СокрЛП и переиспользуются,
   переименовывать данные не обязательно.
3. **Асимметрия фланцев (мелочь).** Поиск сравнивает `" ["+СОКРЛП(Строка(ОбозначениеФланцы))+"]"`,
   а создание пишет `" ["+Стр.ОбозначениеФланцы+"]"` (стр. 2647/2636) — при пробелах в обозначении
   фланцев поиск и создание разойдутся тем же способом. Привести к одному виду (СОКРЛП в обоих).

### Чистка данных (ВЫПОЛНЕНО 20.09.2026 на тестовой базе)

Имена с ВЕДУЩИМИ пробелами — единственный класс, дающий крах формы
(генерат с пустым обозначением «  <материал>» + асимметричный поиск + СокрП БСП).
Скрипт `tools/as_order_loader/cleanup_char_names.bsl` (режимы «Проба»/«Запись`)
переименовал 12 таких элементов в чистое имя (0 конфликтов, БСП приняла все
записи; ссылки документов не затронуты — переименование по ссылке безопасно).
Верификация: имён с ведущим пробелом — 0. Имена с хвостовыми пробелами
(61 шт.) НЕ тронуты намеренно: форма находит их через СокрЛП правой части,
краха они не дают.

## Заметки

- Тот же класс бага закрыт в загрузчике; HTTP-путь (`ВОКЗагрузкаЗаказаHTTP.ЗагрузитьЗаказHTTP`,
  модуль расширения в базе) в репозитории отсутствует — предмет проверки 1С-разработчиком:
  поиск характеристики там должен быть СокрЛП-симметричным тем же аргументом.
- `ПоискХарактеристикиМатериала` (модуль объекта обработки, дамп `docs/модуль ввод нового заказа.txt`,
  стр. 26549–26613) сравнивает без СокрЛП с обеих сторон — симметричен, уязвимости нет,
  но при появлении у владельца «мины» с пробелами тоже промахнётся; стоит привести к СокрЛП.

# Исследование: альтернативы загрузки заказов в 1С (без XML-файлов)

Дата: 05.09.2026. База: клиент-серверная `Srvr="WIN-DM2PLAHAIIL"; Ref="KA_vok-region_test"` (**тестовая**).
Канал исследования: MCP Toolkit (обработка `MCP_Toolkit.epf`, встроенный HTTP-сервер на localhost:6004).

## Текущее состояние

Python генерирует XML-файл → менеджер импортирует его обработкой «модуль загрузки с сайта»
(`docs/модуль загрузки с сайта.txt`) → документ `асСпецификацияЗаказа`.

Недостатки, зафиксированные при приёмке заказа 847:
- файл как посредник: медленно, 1С «зависает» на больших файлах (672 позиции);
- из XML нельзя передать шину на соединение — её выбирает код 1С с дефолтами,
  расходящимися с правилами техотдела (см. `docs/BACKLOG.md`);
- материал подбирается кодом 1С (`асОбщийМодуль.НахождениеМатериалаПоТипу`), а не берётся из XML.

## Что есть в конфигурации (метаданные)

HTTP-сервисы (10): `exchange_dsl_1_0_0_1` (обмен узлами БСП — файловый, не подходит),
`Биллинг`, `ПередачаДанных`, `АСУ_WhatsApp_Service`, `АСУ_JivoChat`, `СерверЛояльности`,
`АСУ_Транскрибация`, `ЭДО`, `АСУ_Телефония`, `Маг1СApi`.

Web-сервисы (18): `CustomerOrdersExchange` — операции `FillCustomersOrders`, `GetCatalogs`,
`GetCustomersOrders` и др. (URI `http://www.1c.ru/CustomerOrders/Exchange`) — **штатный канал
загрузки заказов с сайта** (SOAP). Также `EnterpriseDataExchange_1_0_1_1` (универсальный формат БСП),
семейство `Exchange_*`, `WMSMobileClientExchange*`, `RemoteAdministrationOfExchange*`.

MCP Toolkit: помимо 8 MCP-инструментов (read-only) имеется скрытый REST-эндпоинт
`POST /api/execute_code` с произвольным кодом 1С: переменная `Результат` возвращается в ответе
(проверено: `Результат = 1+1;` → `2`). **Это полноценный канал записи.**

## Варианты загрузки (по убыванию практичности)

### A. Прямая запись через `execute_code` (JSON → объектная модель 1С) — доступно сейчас

Python шлёт JSON с позициями → `execute_code` создаёт
`Документы.асСпецификацияЗаказа.СоздатьДокумент()`, заполняет ТЧ `Товары` (Номенклатура,
Продукт, материал-ссылка, шина-ссылка `МатериалНаСоединение0..3`, t, параметры), `Записать()`.

- Плюсы: нет файлов и XML; полный контроль — можно сразу ставить УГФ-65/95/105 по правилам
  техотдела и точные материалы-ссылки, **решая все 3 пункта BACKLOG**; транзакция
  (`НачатьТранзакцию`/`ОтменитьТранзакцию`) целиком; проверка ссылок до записи; сколько угодно
  позиций без зависания UI.
- Минусы/риски: сырой канал — любой, кто достучится до порта, исполняет произвольный код
  в базе (порт сейчас проброшен SSH-туннелем на сервер — закрыть наружу, по возможности
  включить ID канала в обработке); обработка должна быть запущена (толстый клиент открыт);
  код выполняется в клиентском контексте толстого клиента.
- Улучшение: вместо голого `execute_code` — добавить в обработку (или свою EPF по её образцу)
  метод `CreateOrderFromJSON(json)` с валидацией схемы и белым списком операций.

### B. Программный вызов штатного модуля загрузки

Через `execute_code` создать документ и вызвать те же процедуры, что разбирают XML
(модуль из `docs/модуль загрузки с сайта.txt`), но скормить им структуру данных напрямую.

- Плюсы: поведение 1:1 с ручным импортом (то, что видит и правит техотдел).
- Минусы: тащит все дефолты 1С — баги из BACKLOG остаются; модуль привязан к форме (33k строк),
  вызывать его вне контекста формы может быть нетривиально.

### C. Web-сервис `CustomerOrdersExchange.FillCustomersOrders` (SOAP)

Тот канал, которым сайт грузит заказы. Генерировать SOAP-пакет вместо XML-файла.

- Плюсы: штатный механизм, поддерживаемый конфигурацией.
- Минусы: требует публикации веб-сервисов (IIS) и изучения формата; тот же импортный движок
  с теми же дефолтами; SOAP неудобен.

### D. HTTP-сервис в расширении конфигурации (долгосрочно правильно)

Собственный сервис `POST /hs/vok/order` (серверный код, авторизация, валидация, логирование),
создающий документ по JSON с правилами техотдела на стороне 1С.

- Плюсы: безопасно, быстро (серверный контекст), не зависит от открытого клиента.
- Минусы: нужен их 1С-разработчик и доработка конфигурации/расширения.

### E. Прочее (отвергнуто)

- `exchange_dsl` / EnterpriseDataExchange — файловый обмен узлами, не для поштучной загрузки.
- OData — неудобен для документов с ТЧ, требует публикации.
- COM-connector (`V83.COMConnector`) — внешнее соединение с сервером из Python на Windows-ноуте:
  быстро и серверно, но привязка к Windows, нужна отдельная лицензия внешнего соединения.

## Проверено в ходе исследования

- `POST /api/execute_code`: `{"code":"Результат = 1+1;"}` → `{"success": true, "data": 2}`.
- Оператор `Возврат` вне процедуры запрещён — результат только через переменную `Результат`.
- `execute_query` и MCP-инструменты — read-only (язык запросов 1С не умеет писать).
- Строка соединения ИБ и списки HTTP/Web-сервисов получены через `execute_code` (чтение метаданных).

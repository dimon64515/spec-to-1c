# Логика расчёта цен и загрузки заказов в 1С — база знаний сессии

> Собрано 05.09.2026 по итогам сессии прямой загрузки заказов (пилоты №000000849–000000852).
> Назначение: чтобы следующий агент/разработчик не выяснял заново, как считаются цены,
> какие параметры куда передаются и где подводные камни. Источники истины: дамп модуля
> `docs/модуль ввод нового заказа.txt` (28146 строк) и проверочные пробы через MCP.

## 1. Архитектура загрузки (текущее решение)

Код: `tools/as_order_loader/as_order_loader.bsl` (обработка `асЗагрузкаЗаказаИзJSON`),
инструкция: `tools/as_order_loader/README.md`, бэклог: `docs/BACKLOG.md`.

Пайплайн `ЗагрузитьЗаказ(СтрокаJSON)`:
1. Разбор JSON (массив позиций, контракт — в README).
2. `ЗаполнитьСтроку` — заполняет строку ТЧ `Товары` документа `асСпецификацияЗаказа`.
3. `РассчитатьВсеСтроки` — **один** проход штатной обработки `асВводНовогоЗаказа`
   на все строки разом (см. §2).
4. Запись документа. Цены/площади уже в строках — кнопку «Расчёт» жать не нужно.

Транспорт сегодня: MCP `execute_code` (порт 6004 на ноутбуке с 1С). Контракт JSON
транспорт-независимый; дальше — HTTP-сервис 1С для бота/Битрикса (JSON в теле запроса,
файл в веб-интерфейс грузить не нужно).

## 2. Как считаются цены (выяснено пробами, паритет подтверждён на 851)

### Правильная точка входа

`Обработки.асВводНовогоЗаказа.Создать()` → заполнить ТЧ `Заказы` → один вызов
**`РедактироватьВсеНаКлиенте_ДляИзмененныхВМодуле()`** (дамп, строка 23407).
Именно она стоит за кнопкой «Расчёт». Внутри, по каждой строке с `ТребуетсяПересчет=Истина`:

```
контекст строки → модульные переменные (ПродуктШапка, Материал, размеры, соединения, ...)
→ Расчеты_D() → РасчетФормул() → РасчетКоличестваСоединений()
→ УстановкаПрайсаНаСервере()        (заполняет ТЧ "Прайс" флагами типа цены)
→ РасчетЦен(Стр.Материал, Стр.Материал2)   (цена из регистра, ЦенаЕд, ТипЦены)
→ РасчетЦеныЗаЕдиницу(Стр)          (Сумма = ЦенаЕд × n)
→ пишет обратно в строку: S, M, Отход, Slock, Sclean, V, L_Izd, Себестоимость,
  КоличествоСоединений, Цена, ЦенаЕд, ТипЦеныПоПрайсу(+0), МатериалНаСоединение0..3,
  ОбозначениеСоединения0..3
```

Ловушки, без которых расчёт расходится с интерактивом:
- **Строка пропускается, если `ТребуетсяПересчет` ≠ Истина** — ставить в каждую строку.
- **`ТекущаяПрограмма1С = "КА"`** — реквизит обработки, форма заполняет при открытии;
  в новом объекте пусто. Если базу переведут на УТ/УНФ/БП — поменять в `РассчитатьВсеСтроки`.
- **`УчитыватьЗамкиВРасчетеПлощадиДляСчета = Истина`** — иначе S без замков:
  для 150×150×1250 S=0.75 вместо 0.793 (Slock=0.043). ЦенаЕд занижается пропорционально.
- **`РедактироватьВсеНаКлиентеВМодуле()` (строка 23169) — НЕ ПОДХОДИТ**: в ней нет вызова
  `РасчетЦен`, цены остаются 0.

### Откуда берутся цены

`РасчетЦен(Материал, Материал2)` (дамп, строка 15):
- Запрос к `РегистрСведений.асЦеныПродукции.СрезПоследних(&Дата, Материал=&Материал)`,
  `&Дата = КонецДня(ДатаУстановкиЦен)`.
- `ВыбМатериал = Материал2` (если заполнен), иначе `Материал`; константа
  `асСчитатьПоЦенеМеталлаДляПроизводства=Истина` переключает всегда на `Материал`.
  В базе сейчас Ложь.
- Тип цены — по флагам ТЧ `Прайс` обработки (ставит `УстановкаПрайсаНаСервере()`
  по `СечениеСтр`): Круглое→КС-флаги, Прямоугольное/Переходное→ПС-флаги. Колонка
  регистра = флаг: `ПрямойУчастокПС`, `ФасонныеИзделияПС`, `НестандартныеИзделияКС`,
  `СпиральноНавивной`, `ПрямойУчастокTDCR20/30` и т.д. (полный список колонок —
  в запросе, строки 22–39 дампа).
- `ЦенаЕд = Цена×S + ЦенаПоСпецификации + ЦенаПоСпецификацииВсехМатериалов` (строка 729),
  `Сумма = ЦенаЕд × n`.

### Тип цены «ПоЦенеИзделия» — когда возникает

1. Строка 887: заполнена `Спецификация` строки (шаблон спецификации продукта).
   **Важно:** при загрузке `Спецификация` строки НЕ заполняем из `Продукт.Спецификация` —
   иначе изделия со спецификацией по умолчанию (15-2-1, 16-1-1) получают «ПоЦенеИзделия»
   вместо цены из регистра. Оставляем как в документе (пустую).
2. Строка 846: `ЦенаПоГруппеПродукции <> Неопределено` — считается через
   `асОбщийМодуль.УстановкаЦеныПоГруппеПродукции(...)` при константе
   `асИспользоватьЦеныПоГруппам=Истина`. **Регистр `асЦеныПродукцииПоГруппе` в базе ПУСТ**
   (измерения: ГруппаПродукции, Продукция, ВидСечения, Диаметр, d1–d3, Материал,
   Ширина, Высота, Длина, Угол; ресурсы: Цена, ТарифЗПРабочих, ТарифМонтажа,
   Себестоимость) — ветка не работает.
3. Строка 193–200: продукт **без материала**, но с `МатериалНаСоединение0` —
   цена через `УстановкаЦеныПоСоставномуСоединению(МатериалНаСоединение0, S_Соединения0, Дата)`.
   **Именно так в 847 получили «ПоЦенеИзделия» строки без металла** (710.4, 222, 133.2) —
   это цена шины/УГФ, а не «воздуховод по цене изделия».
4. TDCR-флаги (строка 832).

### Площадь и масса

- `S = ?(УчитыватьЗамкиВРасчетеПлощадиДляСчета, Sclean + Slock, Sclean)` — формула
  повторяется в каждой ветке `РасчетФормул` (напр. строки 5043, 5576, 5705).
  `Slock = L × Lock1`, `Lock1 = асОбщийМодуль.ЗначениеПрипускНаЗамки(ПродуктШапка,0)/1000`.
- `M = (Sclean + Slock + ОтходДляS) × Pz`, где `Pz` = ПлощадьЗнаменатель материала
  (строки 5381–5386, 5585).
- Константы в базе: `асИспользоватьЦеныПоГруппам=Истина`,
  `асРасчетЦеныВоздуховодаСУчетомЦеныФланцев=Ложь`,
  `асСчитатьПоЦенеМеталлаДляПроизводства=Ложь`.

## 3. Параметры строки ТЧ `Товары` (документ) и `Заказы` (обработка)

Без обязательных полей обработка показывает строки пустыми (выяснено в пилоте):

- `Продукт` — **ссылка на `Справочник.асПродукция`** (НЕ Номенклатура!),
  поиск `НайтиПоРеквизиту("Артикул", ...)`.
- `Номенклатура = Продукт.Продукт`; `АртикулПродукции`; `АртикулГруппы` (часть артикула
  до первого дефиса); `ГруппаПродукцииСтр = Продукт.ГруппаПродукции`;
  `СечениеСтр = Продукт.ВидСечения` (перечисление асВидыСечений).
- Количество: `n` и `np`. Толщина: `t` и `t2`.
- Материал: `Материал`, `Материал2` — `Справочник.асМатериалы`, наименование строго
  с двумя знаками толщины: `Рулон оц.(08ПС)0.80`, `Лист.нерж. (AISI 430) 0.80`,
  `Лист черн.(Ст-3)1.20`, `Штрипс оц.(08ПС)0.50`. Поиск `НайтиПоНаименованию(..., Истина)`.
- Соединения: `СоединениеВоздуховода_c0/c1` (круглое сечение) и
  `СоединениеВоздуховода_r0/r1` (прямоугольное) — `Справочник.асСоединениеВоздуховодов`
  («Шина / уголок», «Без соединения»). `МатериалНаСоединение0/1` — `Справочник.асПродукция`:
  «Шина 20 / УГФ 65», «Шина 20 / УГФ 95», «Шина 30 / УГФ 105».
- Размеры: `A0/B0/D0/L0` — исходные; производные `a1..a3, b1..b3, d1..d4, l1..l6,
  p, p1..p3, R, R1..R3, u` — из регистра `асНастройкиПродукции` (см. §4).
- Текст комментария: `КомментарийКПродукцииИзOnLine`.

Перенос строки в обработку — по **общим колонкам** (рефлексией: цикл по колонкам
`О.Заказы.Выгрузить().Колонки`, `З[к.Имя] = СтрД[к.Имя]` в Попытке) — так делают
`РассчитатьВсеСтроки` и проверочные пробы; обратный проход пишет результаты в документ.

## 4. Регистр `асНастройкиПродукции` (производные размеры фасонки)

Без этих размеров шумоглушители дают отрицательную S (`Sring = a1*b1 − A*B`).

- Отбор по `Продукт` (ссылка асПродукция). Поля: `ПараметрПродукции` (имя поля строки:
  a1, b1, d1, p, p1, …), `Вариант`, `КонстантаЗначения`, `ЗависимыйПараметр`, `Оператор`
  (справочник `асАрифметическиеОператоры`: Сложение/Вычитание/Умножение/Деление), `ЧислоX`.
- Вариант1 — константа; Вариант2 — формула `База = Стр[ЗависимыйПараметр]`, применить
  оператор с ЧислоX. Диапазонный Вариант3 в выборках не встречался.
- Правило: применять **только к нулевым полям** (иначе перезапишем размеры из спецификации).
- Примеры (851): 15-2-1 → a1=A0+100, b1=B0+100, p=p1=50; 15-1-1 → d1=D0+100.

## 5. Правила техотдела (приоритет над дефолтами 1С)

- Шина на соединение: 100–350 мм → УГФ-65 (`Шина 20 / УГФ 65`); 400–950 → УГФ-95;
  ≥1000 → УГФ-105 (`Шина 30 / УГФ 105`). По **наибольшему** размеру сечения.
  ⚠ 1С при XML-импорте ставит УГФ-65 только ≤250 (порог константа
  `асИспользованиеШиныУГФ2065До`, диапазоны в справочнике «УсловияНаШинаУголок»,
  код `модуль загрузки с сайта.txt` ~14746–14781 сравнивает по Мин(A,B) вместо Макс) —
  **не решено, в бэклоге**. Прямой загрузчик шину ставит сам по этим правилам.
- Металл: 0.5 и 0.6 не считают — считать 0.55. Толщины по ГОСТ: 100–350 → 0.55;
  400–950 → 0.7; 1000 → 0.8; ≥1100 → 1.0. Дымоудаление — минимум 0.8.
- Воздуховоды: большее число первым (100×150 считать как 150×100). Отводы — как написано.
- Дефлектор = Зонт крышный (синонимы). ЗАСЛОНКИ РУЧНЫЕ = ДК (Дроссель-клапан).
- Пользователь подтверждает: правила техотдела в приоритете (они вбивают заказы вручную
  и правят дефолты 1С).

## 6. Инфраструктура MCP и проверки

- MCP: `POST http://127.0.0.1:6004` — streamable-эндпоинт `/mcp` (хелпер `/tmp/mcp_call.py`,
  сессия `/tmp/mcp_session.id`) и прямой `POST /api/execute_code` с телом `{"code":"<BSL>"}`,
  ответ `{"success":true,"data":...}`; результат код возвращает через переменную `Результат`.
- `execute_code` гоняет фрагмент через `Выполнить`: **нельзя** `Процедура/Функция/Возврат`
  на верхнем уровне — всё инлайн; табы/переводы собирать через `chr(9)`/`chr(10)`.
- Сервер однопоточный: один тяжёлый вызов блокирует остальные. Расчёт 20 строк —
  ~1.5 с; большие объёмы могут «зависать» на 10+ мин. **Не грузить в тесты >50 позиций**
  (пожелание пользователя).
- Сериализатор MCP округляет числа до ~4 значащих разрядов (1276.73 → 1277) — при сверке
  не путать с расхождением.
- Инструменты MCP: execute_query, execute_code, get_metadata, get_event_log,
  get_object_by_link, get_link_of_object, find_references_to_object, get_bsl_syntax_help,
  get_screenshot. **Дампа исходников общих модулей нет** (`асОбщийМодуль` недоступен —
  код `УстановкаЦеныПоГруппеПродукции` и др. не прочитать; get_metadata игнорирует имя
  объекта и отдаёт обзор конфигурации).
- Перечень объектов метаданных через execute_code: цикл `Метаданные.РегистрыСведений` и т.п.
- База: `Srvr="WIN-DM2PLAHII..."` (ноутбук пользователя), `Ref="KA_vok-region_test"`.
  Порт проброшен только агенту, токен не нужен. Конфигурация — КА (отсюда "КА" в
  `ТекущаяПрограмма1С`).
- Эталонные документы: **851** (пилот, 20 поз., интерактивный расчёт — эталон сверки,
  не удалять), 847 (интерактивный, 50 поз., источник типов цен). 848/849/850/852 —
  тестовый мусор, помечены на удаление 05.09.

## 7. Проверенные приёмы (копипаста для проб)

Wholesale-перенос строки документа в обработку и обратно (см. `РассчитатьВсеСтроки`):
цикл по `О.Заказы.Выгрузить().Колонки` с `Попытка З[к.Имя] = СтрД[к.Имя]; Исключение` —
устойчиво к различиям составов колонок.

Отладка цен по одной строке: загрузить строку эталонного документа в `О.Заказы`,
`ТребуетсяПересчет=Истина`, `О.РедактироватьВсеНаКлиенте_ДляИзмененныхВМодуле()`,
сравнить `О.Заказы[0]` с сохранённой строкой (S, Slock, Sclean, Цена, ЦенаЕд, ТипЦены).

Проверка «откуда цена»: прямые вызовы с фиксацией `ОписаниеОшибки()` в переменную
(не `Возврат` — компиляция фрагмента упадёт), дамп ключей возвращённой Структуры.

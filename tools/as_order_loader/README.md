# асЗагрузкаЗаказаИзJSON

Внешняя обработка 1С: создаёт документ **асСпецификацияЗаказа** напрямую из JSON-спецификации —
без XML-импорта, без ручного ввода, со штатным расчётом площадей, масс и цен.

Проверено на тестовой базе (пилоты №000000849–000000851): шины по правилам техотдела
(УГФ-65/95/105), материалы без подмены, производные размеры фасонки, цены из регистра
`асЦеныПродукции` — всё обсчитывается автоматически, без нажатия «Расчёт».

**Паритет цен подтверждён:** логика расчёта — это штатная процедура
`РедактироватьВсеНаКлиенте_ДляИзмененныхВМодуле()` обработки `асВводНовогоЗаказа`
(та самая, что стоит за кнопкой «Расчёт»). На 20 позициях заказа №000000851
программный расчёт дал те же S (включая замки), типы цен и цены, что интерактивный
пересчёт в обработке.

## Состав

- `as_order_loader.bsl` — модуль объекта обработки (весь код).
- `build_execute_payload.py` — генератор inline-BSL payload для `POST /api/execute_code`
  (тот же алгоритм, «распластанный» — процедуры через `Выполнить` не объявить).
  Использование: `build_execute_payload.py positions.json [--mark-delete] > payload.json`,
  затем `curl -X POST http://127.0.0.1:6005/api/execute_code -d @payload.json`.
  ⚠️ BSL-шаблон внутри — в тройных ОДИНАРНЫХ кавычках: в BSL встречаются `"""`.
- `json_positions.py` (корень репозитория) — сборка positions.json из success-строк
  пайплайна: `material_1c_name` (точное имя материала, два знака толщины),
  `shina_by_max_dim` (≤350→65, 400–950→95, ≥1000→105), `build_positions`.

Проверено end-to-end (05.09.2026): 13 позиций из прогона Шипиловского → заказ
№000000852, шины на всех границах по правилам техотдела, материалы без подмены
(оц. → «Рулон оц.(08ПС)», не AISI), цены штатного расчёта, заказ помечен на удаление.
Полный проект одним документом: 286 позиций (весь Шипиловский без 20-2) →
заказ №000000860 за 14 с. Ограничение «~50 позиций на заказ» относится только к
XML-импорту через интерфейс Softvent (там 1С зависает), прямой путь его не имеет.

## Сборка EPF (5 минут в конфигураторе)

1. Конфигуратор → Файл → Новый → Внешняя обработка → имя `асЗагрузкаЗаказаИзJSON`.
2. Открыть модуль объекта, вставить содержимое `as_order_loader.bsl`, сохранить как
   `асЗагрузкаЗаказаИзJSON.epf`.
3. Проверка: в отладке выполнить
   `ВнешниеОбработки.Создать("<путь>\асЗагрузкаЗаказаИзJSON.epf").ЗагрузитьЗаказВернутьJSON(СтрокаJSON)`.

## Точки входа

| Метод | Назначение |
|---|---|
| `ЗагрузитьЗаказ(СтрокаJSON)` | Основной. Возвращает структуру `Успех/НомерЗаказа/Ошибки/Предупреждения` |
| `ЗагрузитьЗаказВернутьJSON(СтрокаJSON)` | То же, JSON-строкой — для HTTP-вызовов |

## Контракт JSON

```json
[
  {
    "article": "1-2-1",
    "qty": 6,
    "thickness": 0.8,
    "material": "Рулон оц.(08ПС)0.80",
    "shina": "95",
    "conn0": "6",
    "conn1": "6",
    "params": {"A0": 400, "B0": 200, "L0": 1250},
    "comment": "..."
  }
]
```

- `article` — артикул из `Справочник.асПродукция`;
- `material` — **точное** наименование из `асМатериалы`, толщина два знака (`0.80`, не `0.8`);
- `shina` — `65` (≤350 мм) / `95` (351–999) / `105` (≥1000) по правилам техотдела; `""` — без шины;
- `conn0/conn1` — код соединения: `6` = «Шина / уголок», `2` = «Без соединения», `""` — не задавать;
- `params` — размеры строки ТЧ (`A0/B0/D0/L0/d1/a1/...`). Угол/радиус/фланец —
  реквизиты ТЧ `u`/`R`/`p` (имена `U0/R0/P0` из пайплайна переименовывает
  `json_positions.params_1c_names`; проверено по метаданным 08.09.2026).

## Как считаются цены (важно для сопровождения)

Подробная база знаний по логике ценообразования 1С, параметрам строки и инфраструктуре
MCP — **`docs/ЛОГИКА_РАСЧЕТА_ЦЕН_1С.md`** (читать перед любыми доработками расчёта).

Расчёт — один проход на все строки (`РассчитатьВсеСтроки`): строки документа копируются
в ТЧ `Заказы` обработки `асВводНовогоЗаказа`, вызывается
`РедактироватьВсеНаКлиенте_ДляИзмененныхВМодуле()`, результаты возвращаются в документ.

Два реквизита обработки, которые интерактивная форма заполняет при открытии,
модуль выставляет явно — без них расчёт расходится с интерактивным:

- `ТекущаяПрограмма1С = "КА"` — конфигурация базы (Комплексная автоматизация);
- `УчитыватьЗамкиВРасчетеПлощадиДляСчета = Истина` — S = Sclean + Slock
  (без этого площадь занижается на площадь замков, цена за изделие — пропорционально).

Если базу переведут на другую конфигурацию (УТ/УНФ/БП) — поменять значение
`ТекущаяПрограмма1С` в `РассчитатьВсеСтроки`.

## Дорожная карта интеграций (транспорт не меняет контракт)

1. **Сейчас:** вызов через MCP Toolkit (`execute_code`) — payload собирает
   `build_execute_payload.py` — или вручную из отладки (EPF).
2. **Далее — бот/Битрикс:** сообщение/файл в Битриксе → webhook → middleware
   (существующий `api.py` / веб-приложение проекта) → HTTP-сервис 1С →
   `асЗагрузкаЗаказаИзJSON.ЗагрузитьЗаказВернутьJSON()` → ответ с номером заказа.
   Файл отдельно грузить в веб-интерфейс не нужно — JSON приходит в теле запроса.
3. HTTP-сервис живёт в конфигурации (нужен 1С-разработчик), обработка остаётся
   внешней — логика загрузки не дублируется.

## Известные ограничения (см. docs/BACKLOG.md)

- В регистре `асЦеныПродукции` не заполнена колонка «СпиральноНавивной» для AISI 430 —
  такие строки грузятся с ценой 0 и предупреждением (вопрос к техотделу).
- Отсутствующие в `асМатериалы` толщины (оц. 2.00/3.00, чёрная 1.50) дают ошибку в ответе.

# Расширение «ВОКЗагрузкаЗаказаHTTP» — сборка за 15 минут

Готовый код для 1С-разработчика. Расширение добавляет HTTP-сервис загрузки
заказа (`асСпецификацияЗаказа`) — транспортная обёртка над проверенной логикой
`асЗагрузкаЗаказаИзJSON` (см. `../as_order_loader.bsl`, `../README.md`).
Типовая конфигурация не изменяется. Полное ТЗ: `docs/ТЗ_HTTP_СЕРВИС_ЗАГРУЗКА_ЗАКАЗА_1С.md`.

## Состав

- `../as_order_loader.bsl` — вся логика загрузки (копия модуля объекта обработки).
- `ДополнениеHTTP.bsl` — точка входа `ЗагрузитьЗаказHTTP` с `order_comment` и
  идемпотентностью по `request_id` (приложить к модулю после кода загрузчика).
- `МодульHTTPСервиса.bsl` — обработчик POST `/vok/order`.

## Шаг 1. Создать расширение

Конфигуратор → Конфигурация → Расширения конфигурации → Создать:
- Имя: `ВОКЗагрузкаЗаказаHTTP`
- Префикс: `ВОК_` (не обязателен, но рекомендован)
- Безопасный режим: **выкл** (нужен доступ к документам и обработке расчёта)
- Использовать в основных ролях: по усмотрению.

Платформа должна быть 8.3.11+ (HTTP-сервисы в расширениях).

## Шаг 2. Общий модуль

В расширении: Общие → Общие модули → Добавить:
- Имя: `ВОКЗагрузкаЗаказаHTTP`
- Сервер: **Да**, Вызов сервера: **Да**, Привилегированный режим: **Да**
  (привилегированный — чтобы не зависеть от прав сервисной учётки; если запрещено
  политикой — снять и выдать роль с правами из ТЗ п. 7).
- Клиент (обычное приложение): Нет.

В модуль вставить **целиком** содержимое `../as_order_loader.bsl` (от шапки до
`#КонецОбласти`), затем **в конец** — содержимое `ДополнениеHTTP.bsl`.

## Шаг 3. HTTP-сервис

В расширении: Общие → HTTP-сервисы → Добавить:
- Имя: `ВОКЗагрузкаЗаказа`, Корневой URL: `/vok`
- Шаблоны URL → Добавить: Имя `order`, Шаблон `/order`
- Методы HTTP → Добавить: `POST` (имя, напр. `ЗаказСоздать`),
  Обработчик: `ЗаказОбработатьPOST`
- Модуль сервиса: вставить содержимое `МодульHTTPСервиса.bsl`
  (обработчик ссылается на `ВОКЗагрузкаЗаказаHTTP.ЗагрузитьЗаказHTTP`).

Итоговый URL: `https://<сервер-1С>/<база>/hs/vok/order`.

## Шаг 4. Публикация

- Администрирование веб-сервера 1С (или конфигуратор: Администрирование →
  Публикация на веб-сервере): опубликовать базу с HTTP-сервисами
  (галка «Публиковать HTTP-сервисы расширений», если есть), перезапустить веб-сервер.
- Публиковать только в локальной сети. Доступ извне — только через VPN/туннель
  с сервера бота.

## Шаг 5. Проверка (curl с сервера бота или машины в сети 1С)

```bash
curl -s -X POST "https://<сервер-1С>/<база>/hs/vok/order" \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{
    "order_comment": "Проверка HTTP-сервиса",
    "request_id": "smoke-test-1",
    "positions": [
      {"article":"1-2-1","qty":2,"thickness":0.8,
       "material":"Рулон оц.(08ПС)0.80","shina":"95","conn0":"6","conn1":"6",
       "params":{"A0":400,"B0":200,"L0":1250},"comment":""}
    ]
  }'
```

Ожидается 200 и `{"Успех": true, "НомерЗаказа": "000000xxx", ...}`.
Повторный вызов с тем же `request_id` → тот же номер + предупреждение
«Заказ уже существует (идемпотентный повтор)» — дубликата в базе быть не должно.

## Шаг 6. Переключение бота (делает Python-сторона, после приёмки)

- В `bitrix.local.yaml` добавить `order_service_url` и ключ; в `config.yaml`
  секции middleware — использовать новый URL вместо `execute_code_url`.
- Правка `bitrix_bot/pipeline.py::load_order_to_1c` (~20 строк): POST JSON
  запроса п. 3 ТЗ вместо payload `{"code": ...}`.
